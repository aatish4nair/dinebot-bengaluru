## AI Restaurant Recommendation Service – Project Architecture

DineBot Bengaluru recommends restaurants for a chosen locality, price range, minimum rating,
and cuisine, with a short LLM-written explanation attached to each result. The codebase is
organized into one Python package per pipeline stage — each folder is named for **what it does**,
not for the order it was built in.

Top-level structure:

- `data_ingestion/` – Downloads and validates the raw dataset from Hugging Face.
- `features/` – Filters and transforms the raw data into query-ready features.
- `recommender/` – Deterministic scoring and ranking engine.
- `ai_explanations/` – LLM-generated natural-language justifications (Groq).
- `web/` – FastAPI backend + HTML/CSS/JS frontend.

Each stage reads the previous stage's output from disk (Parquet files) and exposes a small
Python API for the next stage to call directly (no network hop between stages — they all run
in the same process today).

```
data_ingestion  →  features  →  recommender  →  ai_explanations  →  web
   (raw data)      (clean,        (ranked          (+ 2-line          (UI +
                   filtered        candidates)       explanation)      API)
                   features)
```

---

## data_ingestion/ – Data Ingestion

**Responsibility**: Fetch and persist the raw Zomato dataset from Hugging Face, apply lightweight
validation, and produce a cleaned-but-untransformed dataset for downstream stages.

**Main components**

- `config.py` – `DatasetConfig` (dataset name, split, data directories such as `raw` and `bronze`).
- `dataset_downloader.py` – Downloads the `ManikaSaini/zomato-restaurant-recommendation` dataset
  from Hugging Face, caches it under `data_ingestion/data/raw/`, and persists a raw snapshot to
  `zomato_raw.parquet`.
- `schema_mapping.py` – Maps the raw Hugging Face schema to the canonical schema used by every
  downstream stage.
- `schema_validation.py` – Validates the canonical schema and filters rows missing critical fields
  (name, city, cuisines, rating).
- `ingestion_pipeline.py` – Orchestrates download → map → validate → filter → write
  `data/bronze/zomato_bronze.parquet`.

**Data flow**: Hugging Face → `data/raw/zomato_raw.parquet` → validated/filtered →
`data/bronze/zomato_bronze.parquet`, consumed by `features/`.

---

## features/ – Feature Engineering & Filtering

**Responsibility**: Transform the ingested data into a structure optimized for querying by user
preferences (place, price range, ratings, cuisines), focused on Bengaluru.

**Main components**

- `config.py` – `FeatureConfig` (target city, minimum rating, data layout).
- `filters.py` – Filters records to Bengaluru; normalizes locality values.
- `feature_transformers.py` – Normalizes price into buckets, ratings, and cuisine lists.
- `index_builder.py` – Builds indices/grouped views; persists to `data/silver/` and `data/gold/`.
- `feature_pipeline.py` – End-to-end pipeline: reads `data_ingestion` bronze data, filters,
  transforms, and writes the gold dataset.

**Data flow**: `data_ingestion/data/bronze/zomato_bronze.parquet` → filtered + feature-engineered →
`data/gold/zomato_gold.parquet`, consumed by `recommender/`.

---

## recommender/ – Recommendation Engine Core

**Responsibility**: Turn user preferences into a ranked list of candidate restaurants
(deterministic — no LLM involved here).

User preferences: place (Bengaluru locality), price range, minimum rating, preferred cuisines.

**Main components**

- `config.py` – `RecommendationConfig` (scoring weights, default result count).
- `schemas.py` – `UserPreferences`, `RestaurantRecord`, `Recommendation` (Pydantic models).
- `candidate_selector.py` – Filters the `features` gold dataset by place/price/cuisines/rating.
- `scoring_engine.py` – Scores each candidate on cuisine match, price fit, and rating.
- `recommendation_service.py` – Public API: `get_recommendations(preferences) -> list[Recommendation]`.

**Data flow**: `features/data/gold/zomato_gold.parquet` + `UserPreferences` → filter → score → rank
→ top-K `Recommendation` objects, consumed by `ai_explanations/`.

---

## ai_explanations/ – LLM Orchestration (Groq)

**Responsibility**: Enrich `recommender` output with a concise **2-line explanation** per
restaurant (price suitability, rating, cuisine), generated by a Groq-hosted chat model.

**Main components**

- `config.py` – `LLMConfig` (model, temperature, max tokens, timeouts); loads `GROQ_API_KEY` from
  the project root `.env`.
- `groq_client.py` – Groq chat-completion calls with retries and error handling.
- `prompt_templates.py` – Prompt text: user preferences + candidate restaurants + "respond with
  exactly 2 lines per restaurant".
- `llm_formatter.py` – Builds the prompt from `Recommendation` objects and parses the response
  back into per-restaurant explanations.
- `llm_recommendation_service.py` – Public API: `get_enriched_recommendations(preferences)`.
  Falls back to the un-enriched recommendation (no explanation) if the LLM call fails, rather
  than failing the whole request.

**Data flow**: `UserPreferences` → `recommender.get_recommendations` → prompt → Groq → parsed
explanations → `LLMEnrichedRecommendation` objects, consumed by `web/`.

---

## web/ – Frontend & Backend Integration

**Responsibility**: Serve the DineBot Bengaluru UI — a preferences form plus a ranked,
LLM-explained results list.

A hand-authored HTML/CSS/JS page (native `<select>` dropdowns, no JS framework), served by a
FastAPI backend.

**Main components**

- `config.py` – Dropdown option lists (places, cuisines) and locality-to-region display lookup.
- `preferences.py` – Maps raw form values (`"3.0+"`, `"₹300 - ₹600"`, ...) to `UserPreferences`.
- `api_gateway.py` – Calls `ai_explanations.get_enriched_recommendations` and deduplicates
  results by restaurant name.
- `server.py` – FastAPI app: `GET /` renders the page, `POST /api/recommendations` returns
  ranked, explained results as JSON.
- `templates/index.html` – The page markup/styles/client-side JS.

**Data flow**: Browser form → `POST /api/recommendations` → `preferences.form_to_preferences` →
`api_gateway.fetch_enriched_recommendations` → `ai_explanations` → `recommender` → `features` →
JSON response → rendered result cards.

## Tooling and Implementation Notes

- **Language & libraries**: Python 3.13, `datasets` (Hugging Face) for data loading,
  `pyarrow`/Parquet for on-disk storage, FastAPI + Jinja2 for the web layer, `groq` for the LLM
  client.
- **Configuration**: Root-level `.env` / `.env.example` for secrets (`GROQ_API_KEY`); one
  `config.py` per stage for that stage's own settings.
- **Dependencies**: one root `requirements.txt` (runtime) and `requirements-dev.txt` (adds
  `pytest`) — install with `pip install -r requirements-dev.txt` for local development.
- **Testing**: each stage keeps its own `test_*.py` files alongside its source, run from the
  project root with `pytest`.
